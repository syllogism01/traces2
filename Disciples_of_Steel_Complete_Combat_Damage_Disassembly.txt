DISCIPLES OF STEEL COMBAT DAMAGE ROUTINE — COMPLETE DISASSEMBLY /
EVIDENCE DOCUMENT
================================================================

Purpose

This document consolidates the executable reverse-engineering work
completed so far, in logical execution order. It is intended as a
handoff document for another LLM or reverse engineer whose eventual goal
is to fully disassemble the entire combat damage routine.

The document deliberately separates:

    [PROVEN]       directly established by executable bytes / observed code
    [STRONG]       strongly supported structural interpretation
    [INFERENCE]    plausible gameplay-facing interpretation not yet forced
    [UNKNOWN]      not yet established

The central unresolved chain is still the exact implementation of the
overlay/vector routine 1E11:0026 and the FP helper 124B:00A6. Nothing
below should silently convert those unknowns into guessed formulas.

================================================================ 1.
EXECUTABLE ARCHITECTURE AND ADDRESSING
================================================================

The game is a 16-bit segmented DOS executable. It uses a custom overlay
/ relocation system and software x87 emulation.

Hard warning:

A far runtime address such as:

    04DD:2DDC
    04DD:2F57
    1E11:0056
    1E11:0026
    124B:00A6
    124B:001E

must NOT be converted to a flat file offset by simply taking the offset.

An overlay directory exists around physical 0x2C3C0. Examples of
observed mapping records include:

    0011:0000 -> 0x4A92
    0011:4FC2 -> 0x4776
    0011:9CC0 -> 0x5F92
    0111:0436 -> 0x50D8
    0111:5B4E -> 0x4CDA
    0111:AE6E -> 0x4BF0
    0211:00B6 -> 0x472E
    ...
    0801:CDA0 -> 0x114
    0801:CEB4 -> 0x90

This is consistent with custom Blinker-style overlay / relocation
metadata.

================================================================ 2.
SOFTWARE x87 EMULATION
================================================================

The executable does not contain ordinary native x87 instructions
throughout the relevant code. Floating operations are emulated using DOS
interrupts.

Observed logical mapping:

    INT 34 -> D8
    INT 35 -> D9
    INT 36 -> DA
    INT 37 -> DB
    INT 38 -> DC
    INT 39 -> DD
    INT 3A -> DE
    INT 3B -> DF
    INT 3C -> segment override
    INT 3D -> FWAIT

This matters when decoding raw bytes: apparent instruction boundaries
near floating-point code can be misleading unless the emulator sequences
are reconstructed.

================================================================ 3.
DESCRIPTOR / RESOURCE STRUCTURES
================================================================

The game uses descriptor structures for arrays and resource-backed data.

General observed descriptor layout:

    +00
    +02    backing segment
    +04    backing offset
    +06
    +08
    +0A
    +0C    element size
    +0E    count/dimension-related field

The common constructor is:

    push ...
    ...
    push resource_id
    call 1348:4034

1348:4034 is an array/descriptor constructor and allocator.

Relevant constructor logic around physical 0x1A074:

    MOV BX,[BP+06]
    CMP WORD PTR [BX+02],0000
    JE ...

    MOV CX,[BP+08]
    MOV [BX+08],CX

    MOV AX,[BP+0A]
    MOV [BX+0C],AX

The allocator later includes:

    POP BX
    XCHG AX,DX
    MUL WORD PTR [BX+0C]
    MOV [BX+0A],AX
    ...
    CALL 16108
    ...
    MOV [BX+06],AX
    ...
    MOV [BX+02],SS
    MOV [BX],SI
    ADD [BX+0A],SI

Therefore these are runtime descriptors, not simply compile-time
pointers.

IMPORTANT: 1348:4034 is proven to allocate/describe resources. It is NOT
itself proof of the disk/archive read operation. The actual
archive-reading logic is elsewhere.

================================================================ 4. ITEM
/ ACTION STRUCTURE 116A
================================================================

Constructor:

    PUSH 0000
    PUSH 0008
    PUSH 0002
    PUSH 0101
    PUSH 116A
    CALL 1348:4034

Therefore 116A is an 8-WORD structure.

The important item/action field is +06.

Assembly:

    MOV SI,116A
    MOV BX,0006
    ADD BX,[SI+0A]
    MOV ES,[SI+02]
    MOV AX,ES:[BX]

This reads the current item/action identifier.

The resulting item ID is used to index item property arrays.

Thus:

    item_id = 116A[current + 06]

where “current” denotes the descriptor’s backing/indexing mechanism.

================================================================ 6. 0C06
— DAMAGE FACTOR
================================================================

[PROVEN]

Constructor:

    PUSH 0000
    PUSH 0032
    PUSH 0002
    PUSH 0101
    PUSH 0C06
    CALL 1348:4034

0032 hexadecimal = 50 decimal.

Therefore:

    0C06 = 50 WORD slots

The initialization loop populates item indices 1 through 48.

Conceptually:

    offset = item_index * 2
    0C06[offset] = parsed item value

This is a persistent item-property array.

DIRECT UI PROOF

At approximately physical executable offset 0x34362:

    MOV SI,116A
    MOV BX,0006
    ADD BX,[SI+0A]
    MOV ES,[SI+02]
    MOV AX,ES:[BX]          ; item ID

    SHL AX,1
    MOV BX,AX
    MOV SI,0C06
    ADD BX,[SI+0A]
    MOV ES,[SI+02]

    MOV AX,ES:[BX]          ; 0C06[item]
    MOV [BP-4E],AX

    LEA AX,[BP-4E]
    PUSH AX
    LCALL 0000:4B01

The surrounding UI label is:

    Dam. Factor:

The value displayed is the value read from 0C06[item], and the same
routine writes an edited value back.

Therefore, unequivocally:

    0C06[item] = persistent item Damage Factor

This is executable proof, not inference.

================================================================ 8. THE
CRITICAL C06 COMBAT OPERATION
================================================================

This is the central local damage-factor proof.

Approximately physical executable offset 0x306E7:

    306E7  MOV SI,116A
    306EA  MOV BX,0006
    306ED  ADD BX,[SI+0A]
    306F0  MOV ES,[SI+02]
    306F3  MOV AX,ES:[BX]        ; item ID

    306F6  SHL AX,1
    306F8  MOV BX,AX
    306FA  MOV SI,0C06
    306FD  ADD BX,[SI+0A]
    30700  MOV ES,[SI+02]

    30705  FIMULS WORD [BX]      ; C06[item]

    3070E  LCALL 124B:00A6

Logical reconstruction:

    item   = 116A[current + 06]
    factor = 0C06[item]

    ST(0) = ST(0) * signed_integer(factor)

then:

    124B:00A6(...)

Therefore the exact local chain is:

    Q
     |
     | FIMULS signed C06[item]
     v
    Q * C06[item]
     |
     | LCALL 124B:00A6
     v
    downstream integer / combat result

[PROVEN] The operand to FIMULS is explicitly the signed integer stored
in 0C06[item].

[UNKNOWN] The exact mathematical normalization performed by 124B:00A6.

It is tempting to write:

    Q * C06 / 100

because C06 values look percentage-like.

That is NOT yet executable proof.

There is no directly visible FDIV 100 between FIMULS and the call. The
normalization may occur inside 124B:00A6 or through another
representation.

Safe equation:

    Q' = Q * C06[item]
    result = Normalize_00A6(Q')

NOT YET SAFE:

    result = Q * C06[item] / 100

================================================================ 11.
0286 — CENTRAL DOWNSTREAM DAMAGE / EFFECT AMOUNT
================================================================

[PROVEN]

The ordinary damage-roll loop initializes:

    0286 = 0

Then around physical 0x305EA:

    LEA AX,[BP-38]
    PUSH AX
    LCALL 0000:3E32
    MOV [BP-3C],AX

    MOV AX,[BP-3C]
    ADD [0286],AX

The loop repeats according to:

    [BP-36]

Therefore:

    0286 = SUM of N random-derived roll results

where each roll uses the die-size in BP-38.

This is not merely a register artifact. 0286 is directly consumed by
post-resolution protection/body/resource processing.

An independent broad effect resolver also constructs 0286 from an
incoming effect amount:

    [BP+10] -> 0286

with an optional addition from:

    1E11:05F0

Thus 0286 should be treated as a concrete damage/effect quantity.

================================================================ 15.
CORE COMBAT SCORE
================================================================

The attack/combat score is substantially reconstructed.

The executable obtains:

    R = 1B7A[0C90[0258]]

Then computes:

    CombatScore =
        15 * R
        - 20 * 02C0
        + 0344
        + 5 * 116A[current + 0A]

Original disassembly:

    MOV BX,[0258]
    SHL BX,1
    MOV SI,0C90
    ADD BX,[SI+0A]
    MOV ES,[SI+02]
    MOV AX,ES:[BX]

    SHL AX,1
    MOV BX,AX
    MOV SI,1B7A
    ADD BX,[SI+0A]
    MOV ES,[SI+02]
    MOV AX,ES:[BX]

    MOV CX,000F
    IMUL CX
    MOV BX,AX

    MOV AX,0014
    IMUL WORD PTR [02C0]
    SUB BX,AX

    ADD BX,[0344]
    ADD BX,[BP-14]
    MOV [BP-2E],BX

Therefore:

    R = 1B7A[ C90[0258] ]

    CombatScore =
        15R - 20*02C0 + 0344 + BP-14

where BP-14 is an additional modifier at this point.

================================================================ 25.
DAMAGE ROLL LOOP
================================================================

The normal sequence is:

    determine die_size -> BP-38
                |
                v
    determine N -> BP-36
                |
                v
    0286 = 0
                |
                v
    repeat N times:
        3E32(BP-38)
        add result to 0286

Assembly around 0x305EA:

    LEA AX,[BP-38]
    PUSH AX
    LCALL 0000:3E32
    MOV [BP-3C],AX

    MOV AX,[BP-3C]
    ADD [0286],AX

The loop is controlled by BP-36.

Thus:

    0286 = SUM_i=1..N RNG_DERIVED(die_size)

This is one of the strongest direct links between the damage table and
the downstream combat quantity.

================================================================
28. >100 SPECIAL BRANCH
================================================================

There is a resolver branch when an input exceeds 100.

The structure is:

    02E4 = 0

    excess = argument - 100

    scaled_excess =
        124B:001E(2 * excess)

    02E4 =
        FISTP(
            scaled_excess + SS:[42CD]
        )

Then:

    02E4 = max(20, min(80, 02E4))

Then:

    PUSH [BP+0E]
    CALL 1E11:0026

Immediately:

    FISTP [0286]

This is important.

[PROVEN] The 1E11:0026 call leaves an FP value on the emulator stack and
the immediate FISTP stores that value into 0286.

Thus 1E11:0026 definitely participates directly in production of a
concrete 0286 value on this branch.

Later scaling can do:

    FIMUL WORD [BX]
    FADD SS:[42F4]
    124B:00A6
    FADD DS:[41DC]
    FISTP [0286]

Again, 0286 is a working/scaled combat quantity.

================================================================ 29.
1E11:0026 — CURRENT STATUS
================================================================

1E11:0026 is NOT a missing ordinary function.

It is the sixth 6-byte overlay vector in the blCOMBAT1 vector block.

The damage routine invokes it as:

    PUSH [BP+0E]
    LCALL 1E11:0026

In the relevant path:

    [BP+0E] = &0204

Therefore 0026 receives a pointer to the location/action selection
